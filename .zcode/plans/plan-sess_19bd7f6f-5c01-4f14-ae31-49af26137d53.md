# 将 tis-3.4.0 的 TIS 定制合并到基于 release-3.7.0 的新分支 tis-3.7.0

## Context

TIS 项目 fork 自 apache/flink-cdc，在 `tis-3.4.0` 分支（= 上游 `release-3.4.0` tag + 16 个自定义提交）上做了大量定制：4 个新连接器模块（dameng-cdc、mysql-cdc-tis、kafka pipeline、iceberg-tis pipeline）、paimon/kingbase/composer 增强、pom 模块注册等。现上游已发布 `release-3.7.0`，需要把定制带到新版本之上。工作区当前干净，无未提交改动。

用户已确认：**单次 merge**（产生一个 merge commit，保留 16 个提交记录）；**冲突由我自动解决**（以上游 3.7.0 代码为基准，重新套用 TIS 增强）。

## 执行步骤

### A. 拉取上游 tag
1. `git remote add apache https://github.com/apache/flink-cdc.git`（若已存在则跳过）
2. `git fetch apache refs/tags/release-3.7.0:refs/tags/release-3.7.0 --no-tags` —— 只拉该 tag，不刷入上游全量 tags（需要网络，若沙箱拦截则关闭沙箱执行）
3. 验证：`git rev-parse release-3.7.0^{commit}` 确认 tag 就位

### B. 建分支并合并
4. `git switch -c tis-3.7.0 release-3.7.0`
5. `git merge tis-3.4.0 --no-ff`，预期产生冲突，逐个解决

### C. 冲突解决原则（预测的冲突热点及处理方式）
- **pom / 模块列表类**（根 `pom.xml`、`flink-cdc-connect/**/pom.xml`、`flink-cdc-composer/pom.xml`）：以上游 3.7.0 的结构为基准，把 TIS 的模块条目、profile、版本属性重新加入
- **代码类**（`PaimonMetadataApplier`、`PaimonSink`/`PaimonCommitter`/`PreCommitOperator`/`BucketAssignOperator`、`FlinkPipelineComposer`、`BinaryRecordDataGenerator` 等，上游 3.4→3.7 有演进）：以上游 3.7.0 新实现为基准，将 TIS 增强点（col comment、metrics、isAtOrAfter 等行为修正）移植到新代码；若上游已重写等价逻辑则以 TIS 语义为准调整
- **TIS 独有文件/模块**（dameng、kingbase、mysql-cdc-tis、kafka、iceberg-tis、docs、install.sh、diff.txt）：仅单侧修改，无冲突，原样保留
- 解决后以默认信息提交 merge commit：`Merge branch 'tis-3.4.0' into tis-3.7.0`

### D. 验证
6. 编译受影响模块：`mvn -DskipTests compile -pl` 根聚合下的受影响模块（composer、paimon、pipeline-connectors 聚合、dameng-cdc、kingbase-cdc、mysql-cdc-tis、kafka、iceberg-tis）`-am`
7. 重点排查 TIS 独有模块中 vendored 的 Debezium 覆盖类（kingbase 的 `io.debezium.connector.postgresql.*`）——上游 3.4→3.7 若升级了 Debezium 版本可能出现编译错误，做小量 API 适配修复
8. 修复过程中如需提交，追加到 merge commit（amend）

### 收尾
- 汇总报告：每个冲突文件的处理决策、编译结果
- **不推送远端**——push 到 origin 由你确认后再执行（或你自行执行）

## 验证方式
- `git log --oneline --graph` 确认 tis-3.7.0 = release-3.7.0 + 16 个 TIS 提交 + 1 个 merge commit
- `git diff tis-3.4.0..tis-3.7.0 -- <TIS 独有模块>` 抽查确认无丢失
- `mvn -DskipTests compile` 全绿
